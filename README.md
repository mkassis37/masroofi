# مصروفي

**مصروفي** تطبيق جوال عربي لإدارة الحسابات المالية الشخصية وتسجيل الدخل والمصروفات والتحويلات بين النقد والحسابات البنكية. صُمم بواجهة عربية من اليمين إلى اليسار، مع دعم العملات المتعددة، ومن بينها الدينار الأردني كخيار افتراضي والشيكل الإسرائيلي، وإظهار المبالغ بثلاث منازل عشرية.

> هذا المستودع يحتوي على تطبيق مصروفي المستقل. لا تخلط بينه وبين مشروع «محفظتي» الموجود في مستودع آخر.

## المزايا الرئيسية

| المجال          | ما يقدمه التطبيق                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------- |
| القيود المالية  | تسجيل دخل أو مصروف مع البيان والتاريخ والحساب والعملة والتصنيف عند الحاجة.                          |
| الحسابات        | حساب نقدي وعدة حسابات بنكية يمكن إضافتها وتعديلها وحذفها وفق القيود المرتبطة.                       |
| التحويلات       | تحويل بين أي حسابين، مع حساب الرصيد حسب العملة المختارة دون جمع عملات مختلفة في إجمالي واحد.        |
| العملات         | قائمة عملات عالمية، والدينار الأردني في المقدمة، مع ترتيب العملات المستخدمة حديثًا في أعلى القائمة. |
| سجل الحركات     | بحث بالبيان، تصفية حسب نوع الحركة أو العملة، تعديل وحذف مع تأكيد.                                   |
| التقارير        | تقارير شهرية وسنوية وتقارير للحركات المحددة، مع تصدير CSV وPDF وملخص أرصدة العملات.                 |
| التصنيفات       | تصنيفات افتراضية ومخصصة للمصروفات مع لون وأيقونة ورسم يوضح نسب الإنفاق.                             |
| النسخ الاحتياطي | إنشاء واستعادة نسخة JSON يدويًا ومشاركة الملف إلى Google Drive أو البريد.                           |
| الحماية         | قفل بالبصمة أو مصادقة الجهاز، والتحقق من ملفات الاستعادة وإنشاء نسخة أمان قبل الاستبدال.            |
| التفضيلات       | حجم الخط، مستوى الإضاءة، اللغة العربية أو الإنجليزية، وتذكير دوري بالنسخ الاحتياطي.                 |

## المتطلبات

يلزم لتشغيل المشروع محليًا تثبيت **Node.js 20 أو أحدث**، ومدير الحزم **pnpm 9.12.0** أو إصدار متوافق، وGit. يعتمد المشروع على Expo SDK 54 وReact Native، ويمكن تشغيله على الويب أو على جهاز Android أو iOS.

للتطوير على جهاز فعلي، ثبّت Expo Go على الهاتف وتأكد من اتصال الهاتف والحاسوب بالشبكة نفسها. يحتاج تشغيل Android إلى Android Studio أو جهاز Android متصل، بينما يحتاج تشغيل iOS إلى macOS وXcode.

## التثبيت

استنسخ المستودع ثم ادخل إلى مجلده:

```bash
git clone https://github.com/mkassis37/masroofi.git
cd masroofi
```

ثبّت الاعتمادات باستخدام pnpm:

```bash
pnpm install
```

إذا لم يكن pnpm مثبتًا، يمكن تثبيته عبر Corepack:

```bash
corepack enable
corepack prepare pnpm@9.12.0 --activate
```

تحقق من سلامة TypeScript والاعتمادات قبل التشغيل:

```bash
pnpm check
```

## التشغيل المحلي

لتشغيل خادم التطوير وخادم Expo للويب معًا استخدم:

```bash
pnpm dev
```

يفتح Expo للويب على المنفذ `8081` افتراضيًا، بينما يعمل خادم API المحلي على المنفذ `3000`. يمكن تغيير منفذ Expo عند الحاجة:

```bash
EXPO_PORT=8082 pnpm dev:metro
```

لتشغيل واجهة Expo للويب فقط:

```bash
pnpm dev:metro
```

ولتـشغيل خادم API فقط:

```bash
pnpm dev:server
```

> في بيئة التطوير المحلية، يبقى التخزين المحلي على الجهاز هو المسار الأساسي. لا تضع مفاتيح أو كلمات مرور داخل ملفات المشروع أو داخل سجل Git.

## تشغيل التطبيق على الهاتف

بعد تثبيت الاعتمادات، شغّل خادم Expo:

```bash
pnpm dev:metro
```

يمكنك فتح عنوان Expo الظاهر في الطرفية باستخدام Expo Go. ولإنشاء رمز QR المساعد للمشروع استخدم:

```bash
pnpm qr
```

لتشغيل Android من بيئة التطوير:

```bash
pnpm android
```

ولتجهيز التشغيل على iOS من macOS:

```bash
pnpm ios
```

تظهر أيقونة «مصروفي» المرفقة في موارد التطبيق، بما في ذلك أيقونة الهاتف وصورة شاشة البداية وموارد Android والويب. ظهور الأيقونة النهائية على الهاتف يتطلب إعادة بناء التطبيق أو إعادة تثبيته بعد تغيير الموارد.

## إصدار Android عبر GitHub Releases

يحتوي المستودع على سير عمل GitHub Actions في `.github/workflows/android-release.yml`. عند دفع tag يبدأ بـ `v`، يتحقق workflow من TypeScript، ويبني APK عبر EAS، ثم يرفعه تلقائيًا إلى GitHub Release. هذا المسار لا يضع مفاتيح أو رموز دخول داخل المستودع.

لإعداد البناء مرة واحدة، أنشئ مشروعًا في [Expo Application Services](https://expo.dev/) ثم أضف السرّين التاليين في إعدادات مستودع GitHub تحت **Settings → Secrets and variables → Actions**:

| السر             | الغرض                                    |
| ---------------- | ---------------------------------------- |
| `EXPO_TOKEN`     | رمز وصول EAS لبناء التطبيق غير التفاعلي. |
| `EAS_PROJECT_ID` | معرّف مشروع EAS المرتبط بتطبيق مصروفي.   |

بعد حفظ السرّين، أنشئ tag وادفعه:

```bash
git tag v1.0.0
git push github v1.0.0
```

بعد انتهاء GitHub Actions، افتح تبويب **Releases** في المستودع ونزّل ملف `masroofi-v1.0.0.apk`. يجب تثبيت APK على جهاز Android يتيح تثبيت التطبيقات من خارج المتجر. ملف APK الناتج من ملف `preview` مخصص للتجربة والتوزيع الداخلي، وليس توقيع متجر Google Play النهائي.

يتحقق التطبيق من أحدث إصدار مستقر في GitHub عند بدء تشغيل نسخة Android، ثم يعيد الفحص عند عودة التطبيق إلى المقدمة بعد فترة انتظار. إذا وجد tag أحدث من النسخة المثبتة وبداخله ملف APK، يظهر تنبيه باللغة الحالية مع زر يفتح رابط تنزيل النسخة الجديدة. لا يثبت Android ملف APK بصمت؛ يلزم تأكيد المستخدم أثناء التنزيل والتثبيت، وقد يلزم السماح بالتثبيت من هذا المصدر في إعدادات الجهاز.

يمكن تشغيل البناء يدويًا أيضًا من تبويب **Actions** عبر workflow dispatch. لا تنشئ tag جديدًا بنفس الاسم إذا كان الإصدار موجودًا؛ استخدم رقم إصدار جديدًا مثل `v1.0.1`. يجب أن تكون الإصدارات مستقرة وليست draft أو prerelease حتى يتعرف عليها فاحص التحديثات.

## الاختبارات وفحوص الجودة

نفّذ الأوامر الآتية قبل إرسال تغييرات جديدة:

```bash
pnpm check
pnpm test
pnpm lint
```

لتنسيق الملفات تلقائيًا:

```bash
pnpm format
```

تشمل الاختبارات منطق حساب الأرصدة، التحويلات، العملات المتعددة، وتحقق البيانات. إذا أضفت ميزة مالية جديدة، أضف اختبارًا مستقلًا لمنطقها قبل تعديل الواجهات.

## قاعدة البيانات والخدمات الاختيارية

المسار الافتراضي للتطبيق هو التخزين المحلي على الجهاز، وهو مناسب للاستخدام دون اتصال. يحتوي المشروع أيضًا على طبقة خادم وDrizzle للاحتياجات الاختيارية، ولا ينبغي تفعيل قاعدة بيانات أو خدمة سحابية في بيئة إنتاجية إلا بعد إعداد متغيرات البيئة وقواعد الوصول المناسبة.

عند استخدام قاعدة البيانات المحلية أو طبقة Drizzle في بيئة تطوير مهيأة، يمكن تشغيل:

```bash
pnpm db:push
```

لا ترفع ملفات `.env` أو `.env.local` أو مفاتيح OAuth أو مفاتيح قواعد البيانات إلى GitHub. استخدم مدير الأسرار أو متغيرات البيئة في بيئة التشغيل.

## النسخ الاحتياطي والاستعادة

من شاشة الإعدادات اختر إنشاء نسخة احتياطية، ثم احفظ ملف JSON في مكان آمن مثل Google Drive أو البريد الإلكتروني. للاستعادة، اختر ملف النسخة من الجهاز واتبع رسالة التأكيد. يتحقق التطبيق من بنية الملف وينشئ نسخة أمان من البيانات الحالية قبل الاستبدال.

النسخ اليدوي هو المسار الموصى به عند عدم إعداد مزامنة خارجية. لا تشارك ملف النسخة الاحتياطية مع أشخاص آخرين لأنه قد يحتوي على كامل سجلاتك المالية.

## قواعد العملة والتحويل

كل حركة تحتفظ برمز العملة الخاص بها. عند التحويل، يجب اختيار العملة نفسها في الحساب المصدر والوجهة؛ التطبيق لا يحوّل أسعار الصرف تلقائيًا ولا يجمع أرصدة عملات مختلفة في قيمة واحدة. إذا احتجت تحويلًا بين عملتين، سجّل العملية بسعر صرف يحدده المستخدم وفق سياسة محاسبية واضحة.

تُعرض المبالغ افتراضيًا بثلاث منازل عشرية، مثل `125.500`. تغيير طريقة العرض لا يعني تغيير الدقة الداخلية للبيانات القديمة.

## بنية المشروع

```text
app/                 شاشات Expo Router والتبويبات
components/          مكونات الواجهات والنوافذ
lib/                 الحالة المالية، الحسابات، العملات، PDF والتفضيلات
hooks/               Hooks الخاصة بالثيم والمصادقة والألوان
assets/images/       الأيقونة وشاشة البداية وموارد المنصات
server/              خادم API وطبقة الخدمات الاختيارية
shared/              الأنواع والثوابت المشتركة
tests/               اختبارات Vitest
app.config.ts        إعدادات Expo وهوية التطبيق
package.json         أوامر التشغيل والاعتمادات
```
